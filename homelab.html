Detection Engineering Homelab

Emulate → observe → detect → tune

atlas · Dell Precision T5810 · Proxmox VE

A detection engineering lab built from scratch: a segmented environment with a Windows Active Directory domain, a Wazuh single-node SIEM and deliberately vulnerable targets, with pfSense enforcing isolation between the lab and the host network. Attack activity is emulated from a Kali VM and mapped to MITRE ATT&CK, driving custom detection rules and tuning against real telemetry.

This page is the running spec sheet for the build — what is online, what needs attention and what the next upgrade buys.

Operational

Isolated lab · no inbound exposure · no production data

Processor Intel Xeon E5-2680 v4 Broadwell-EP, 14C/28T, 2.4 GHz base / 3.3 GHz turbo, 35 MB L3, 120 W TDP.
Socket / board LGA 2011-3 · Dell Precision T5810 Single-socket workstation chassis.
Firmware A34 — BIOS update required for the v4 stepping pre-install task Flashed before relying on the CPU. There is no BIOS flashback on this board, so a POST-capable CPU has to be seated first.
Host display Basic PCIe VGA for console and recovery The Xeon has no integrated graphics, so the node runs headless over SSH and the web UI.
Installed 24 GB DDR4 ECC RDIMM — 6 × 4 GB, a mix of 2133 MHz and 2400 MHz The mixed kit clocks down to 1866 MHz across the board.
Slots 8 DIMM slots · 6 channels filled The current fill leaves room to move to one DIMM per channel for best speed.
Upgrade path 8 × 16 GB → 128 GB, filling every channel planned Enough to run the full stack simultaneously. Preferably all 2400 MHz modules, with an overnight memtest86+ pass before trusting used sticks.
ZFS ARC cap zfs_arc_max = 4 GB set Essential at 24 GB, so ZFS caching cannot starve the guests.
Boot / VM disks 256 GB SATA SSD · LVM-thin Volume group pve → pve/root for the OS and pve/data for guest disks. The tightest constraint in the build — thin-pool headroom needs watching.
Bulk pool gaia — ZFS mirror, 2 × 2 TB WD RE4 (WD2003FYYS) at 3 Gb/s, with datasets gaia/backup and gaia/iso. A mirror survives a dead disk, not an rm — snapshots are not backups.
Pool geometry ashift=12 · compression=lz4 · atime=off set ashift is permanent, and 12 keeps future 4Kn replacements drop-in.
Data integrity Monthly scrub · SMART long test · ZED email alerts verify Given the age of the drives, confirm the scrub cron covers gaia and that a degraded-pool email actually sends.
Highest-value upgrade 1 TB NVMe on a PCIe adapter planned Boot stays on the SATA SSD and guest disks move to NVMe — the single best ~$80 in the build.
PSU Dell 685 W (DP/N 0VYRCP) · active PFC
UPS ION F10 · 850 VA / 490 W · simulated sine The vendor states APFC support, and sizing is comfortable at roughly 17% load at idle with the tower alone on battery.
Open question Stepped waveform against an active-PFC PSU test under load Transfer-test at real load with stress-ng, both directions, 5–10 cycles. A clean idle transfer is not proof; PFC stages fault hardest when busy.
Auto shutdown NUT on Proxmox over the USB link Likely nutdrv_qx (Voltronic/Megatec class). Trigger on remaining runtime of about 8 minutes rather than battery percentage, which these units report poorly.
On battery Tower only current The monitor sits on surge-only. Guest shutdown order is set so the domain controller flushes before the host powers off.
Planned on battery Modem · router · switch planned Roughly 20–30 W combined. Adding them keeps the network up through brief outages and barely dents runtime.
Domain controller Windows Server · lab.local AD DS and DNS — the attack surface for the detection loop.
Domain client Windows, joined to lab.local
Attacker Kali Linux Impacket, Rubeus and hashcat for technique emulation.
SIEM Wazuh single-node Around 8 GB and 4 cores is realistic; the indexer heap is the real RAM cost. ISM retention set early.
Targets OWASP Juice Shop · DVWA
Containers Pi-hole and supporting services in LXC Unprivileged LXC over VMs to save RAM. Community scripts are fine for plumbing; the security path is hand-built.

At 24 GB the lab runs a slice at a time, snapshotting or stopping idle guests. At 128 GB the whole stack runs at once.

Physical 1 × onboard gigabit The home router stays the real internet path; pfSense is a lab-internal gateway, not the house router.
Gateway pfSense on an isolated bridge (vmbr1, no physical port) NATs the lab outbound for updates.
Segments Attacker LAN · Victim LAN Rules permit attacker → victim and deny lab → home LAN.
Isolation gate Verify the lab cannot route to the home LAN before targets go live
Upgrade path Intel i350-T4 NIC · managed switch for VLANs planned
Telemetry Sysmon (SwiftOnSecurity baseline) → Wazuh agent → indexer Sysmon-fed detection is far stronger than raw Windows logs.
Framework MITRE ATT&CK — every technique mapped by ID
Kerberoasting T1558.003 · rule 100200 plus a volumetric rule planned The 4769 RC4 tell, with machine-account noise tuned out and an AES-evasion backstop.
DCSync T1003.006 planned
LSASS access T1003.001 planned
Password spray T1110.003 planned

The loop — emulate, find the telemetry, write the rule, then tune against legitimate activity — is the point of the lab. The tuning is what signals real skill.
